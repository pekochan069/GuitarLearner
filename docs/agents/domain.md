# Domain docs

This repository uses a single-context layout:
`GLOSSARY.md` at the root and decisions under `docs/adr/`.

Before exploring, read the glossary and ADRs relevant to the work.
If they do not exist, proceed silently. Create them through domain-modeling
when terminology or decisions are resolved.

Use the glossary's terms in issues, proposals, and tests.
If a required concept is missing, reconsider the term or note the gap
for domain-modeling.

Explicitly identify any proposal that contradicts an existing ADR.
